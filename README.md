# Luma Player

Самостоятельный офлайн-аудиоплеер для Windows на Electron, React и TypeScript. Исходники находятся в корне этого репозитория; для работы не нужны VK, токен API или аккаунт. Пять коротких демотреков входят в поставку: их можно послушать сразу, даже если на компьютере нет музыки.

## 1. Запуск с нуля на Windows

### Готовый установщик — без Node.js и Git

Если для нужной ветки уже прошла сборка, откройте в GitHub **Actions → Windows build**, выберите успешный запуск и скачайте архив **Luma-Player-Windows-x64** из раздела **Artifacts**. Распакуйте архив. Внутри два варианта:

| Файл | Что делать |
| --- | --- |
| `Luma-Player-Setup-0.1.0-x64.exe` | Запустите установщик, выберите папку и откройте **Luma Player** через меню «Пуск». Устанавливается для текущего пользователя. |
| `Luma-Player-Portable-0.1.0-x64.exe` | Запустите напрямую, без установки. Настройки и медиатека всё равно сохраняются в профиле Windows, а не рядом с `.exe`. |

Цель сборки — **Windows 10/11 x64**. Тестовые сборки не подписаны: Windows может предупредить о неизвестном издателе. Используйте только файл из доверенного запуска Actions или собранный вами из исходников. Если артефакта ещё нет, выполните шаги ниже.

### Запуск из исходников и сборка своих `.exe`

1. Установите [Node.js 22 LTS](https://nodejs.org/) (версию **22.12 или новее** в ветке 22.x). Установите [Git](https://git-scm.com/download/win), если будете клонировать, а не распаковывать ZIP.
2. Скачайте исходники **этой ветки** и распакуйте их. Если ветка опубликована на GitHub, то же самое можно сделать через PowerShell:
   ```powershell
   git clone --single-branch --branch arena/60be7532-vkx-modded https://github.com/JohnBirlich/VKX-Modded.git
   cd VKX-Modded
   ```
3. Откройте PowerShell в папке с `package.json` и выполните:
   ```powershell
   node --version
   npm.cmd ci
   npm.cmd run dev
   ```
   Откроется приложение Electron. Интернет нужен при установке зависимостей и первой загрузке Electron, не для прослушивания. `npm.cmd` работает и там, где PowerShell блокирует запуск `npm.ps1`.
4. Чтобы собрать установщик и portable, закройте окно разработчика и выполните:
   ```powershell
   npm.cmd test
   npm.cmd run dist:win
   ```
   Оба `.exe` появятся в **`release/`**. `npm run build` выполняет проверку типов и сборку, а `npm start` запускает собранную версию из исходников без Vite.

Если порт `5174` занят, перед `npm.cmd run dev` задайте, например, `$env:LUMA_DEV_PORT = '5184'`. Если `npm ci` не видит Node.js сразу после установки, переоткройте терминал. GitHub Actions также собирает `.exe` при отправке ветки или открытии PR; workflow не публикует релизы.

## 2. Проверка без установки: веб-превью

Откройте живое превью **Luma Player** в Arena. Для запуска браузерной версии у себя:

```sh
npm ci
npm run dev:web
```

Откройте адрес из терминала (обычно `http://localhost:5173`). Веб-версия воспроизводит те же демотреки и принимает ваши файлы. Она не тестирует кнопки окна Electron, поведение установленной программы и интеграцию с Windows. Если хранилище браузера доступно, файлы остаются у текущего браузерного профиля в IndexedDB; при запрете хранилища или недостатке места они доступны до закрытия вкладки. Загрузки на сервер нет.

## 3. Что проверить

1. Нажмите **Воспроизвести**: должен заиграть `Afterimage`, а ползунок — пойти вперёд. Поставьте на паузу, перемотайте, проверьте громкость и отключение звука.
2. В **Очереди** перетащите следующий трек за его номер или поменяйте порядок кнопками `… → Выше / Ниже`. Проверьте удаление из очереди, перемешивание и переключение повтора: выкл. → вся очередь → один трек.
3. Откройте **Эквалайзер**. Выберите пресет, отрегулируйте пять полос и предусиление во время воспроизведения. Переключатель позволяет сравнить звук с обработкой и без неё.
4. Нажмите **Добавить музыку** или перетащите в окно несколько аудиофайлов. В разделе **Моя музыка** найдите трек по названию, исполнителю или альбому. Из файла читаются теги и обложка; если тегов нет, используется имя файла. Кнопка **Демотреки** скрывает или возвращает встроенную коллекцию.
5. Закройте и снова откройте приложение: добавленные файлы, выбранный трек, очередь, громкость и эквалайзер должны остаться. В Windows дополнительно проверьте сворачивание, разворачивание окна и медиаклавиши во время активной сессии воспроизведения.

Поддерживаемые расширения при импорте: **MP3, WAV, FLAC, OGG/OGA, OPUS, M4A, AAC и WEBM**. Воспроизведение зависит от аудиокодека, а не только от расширения; для первой проверки лучше использовать MP3 или WAV.

| Клавиши | Действие |
| --- | --- |
| `Ctrl+O` | Добавить музыку |
| `Пробел` или `K` | Воспроизвести / пауза |
| `←` / `→` | Перемотка на 5 секунд |
| `M` | Отключить или вернуть звук |
| `Q` | Показать / скрыть очередь |

Горячие клавиши воспроизведения работают, когда фокус вне полей ввода и кнопок. Медиаклавиши и метаданные для ОС передаются через Chromium Media Session при активном воспроизведении; Windows сама выбирает активный плеер, если их несколько.

## Где хранятся данные

В настольной версии `%APPDATA%\Luma Player` содержит индекс `library.json`, кеш обложек и настройки. Режим `npm run dev` использует отдельную папку `%APPDATA%\Luma Player Dev`. Музыка остаётся в исходных папках. Удаление трека из медиатеки не удаляет его с диска; если файл перемещён, добавьте его заново с нового места. Для полного сброса закройте плеер и переименуйте соответствующую папку профиля. В веб-версии для сброса очистите данные сайта, на котором открыт плеер.

## Структура проекта

- `src/` — интерфейс, транспорт, Web Audio, очередь и адаптер локальной библиотеки. Источник треков отделён от плеера, чтобы при необходимости добавить отдельную интеграцию через официальный API.
- `electron/` — окно, импорт тегов, локальный индекс и выдача аудио с поддержкой перемотки. Рендерер работает без Node.js, через ограниченный IPC-мост.
- `.github/workflows/windows.yml` и `electron-builder.yml` — сборка Windows x64 и получение двух установочных файлов.
- `npm test` — автоматические тесты очереди, импорта и локальной выдачи аудио. `scripts/make-demos.py` — исходник оригинальных демонстрационных сигналов; Python и FFmpeg нужны только для их регенерации.
