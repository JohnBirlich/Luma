# Windows 1.0.0: что работает и что требуется проверить

Разработка ведётся для Windows 10/11 x64. **0.20.0** — промежуточный выпуск, не релиз 1.0.0. Android не входит в этот этап.

| № | Функция | Состояние в ветке |
|---|---|---|
| 1 | Одна запись, несколько источников | Перенос предпочитает однозначное совпадение с файлом; доступен выбор другого файла или сохранённой записи. Поиск группирует результаты поддерживаемых каталогов с локальным файлом, когда сходятся название, исполнитель, длительность, альбом или ISRC. Разные явно указанные версии и конфликтующие ISRC не объединяются. Совпадения без общего ISRC отмечены как похожие, а не подтверждённые. |
| 2 | Discord Rich Presence | Настройки → Интеграции. Выключено по умолчанию. Для проверки нужен публичный Application ID и запущенный Discord Desktop. Локальный IPC передаёт только текущие название и исполнителя, очищает статус при паузе или выключении. Нужна проверка отображения с реальным клиентом. |
| 3 | Открытие ссылок VK из других приложений | NSIS регистрирует `luma-player://open?url=<закодированная-ссылка>`. Разрешённые VK-треки и плейлисты появляются в окне Luma, без сетевого запроса и автозапуска. Для воспроизведения внутри окна ещё нужен доступ VK для Luma. Обычную ассоциацию браузера для `https://` приложение не меняет. |
| 4 | OTA | В «Главная → Обновления» и в настройках версии — проверка стабильного GitHub-релиза. Установка из приложения включается только в подписанной x64-сборке с закреплённым сертификатом; требует подтверждения. Нужен тест подписанного обновления на двух версиях. Portable и неподписанные выпуски, включая 0.20.0, обновляются вручную. |
| 5 | Воспроизведение | Таймер сна на карточке «Сейчас играет» и в настройках воспроизведения. Кроссфейд между файлами, EQ, качество Jamendo и системные команды сохранены. Физические медиаклавиши и панель на заблокированной Windows требуют ручной проверки. |
| 6 | Синхронный текст | Клик или клавиатура на строке перемещает текущую позицию в «Сейчас играет» и караоке. Автопрокрутка остаётся отдельной настройкой; обычный текст не получает ложных таймкодов. |
| 7 | Офлайн VK | Нет. Нужны отдельное разрешение VK на офлайн, официальный способ загрузки трека/списка и правила срока хранения. Временный кэш Commons не считается офлайн VK. |
| 8 | Просмотр переноса | Можно посмотреть совпадения, найти другой трек в медиатеке, явно выбрать вариант или пропустить строку. Повторы и лимит пересчитываются. Без сохранения исходные списки и очередь не меняются. Готовый CSV/TXT со списком VK можно открыть через отдельный пункт мастера; авторизованного переноса из учётной записи VK/Яндекса нет. |
| 9 | Приватная синхронизация Unison | Есть локальный импорт резервной копии Unison v1 с выбором списка и предпросмотром. Сетевой синхронизации нет: нужен согласованный сервер и тестовый аккаунт от владельца. Luma не загружает файлы на сервер и не изменяет резервную копию. |
| 10 | Поделиться треком или плейлистом, открыть VK/Яндекс | Локальные треки и списки можно передать как `.luma.json` без медиа и путей к файлам. Поддерживаемую запись Openverse можно передать ссылкой Luma и открыть после проверки карточки. VK/Яндекс пока распознаются, но не играют в Luma. |
| 11 | Своя лайк-подборка | Любой плейлист Luma можно добавить в «Любимое Luma». Это локальная операция. Отправка лайков в Яндекс или YouTube требует разрешённых API записи и отдельного явного действия для каждого отправления. |
| 12 | Резервная копия | По желанию пользователя Luma при сбое онлайн-источника запускает один файл из библиотеки, если он совпадает по ISRC, метаданным и длительности. Не меняет сохранённый плейлист, не запускает второй сетевой запрос и не обходит ограничения исходного источника. |
| 13 | Единый поиск | Общий интерфейс для файлов Windows и подключённых открытых каталогов, локальная очищаемая история подтверждённых запросов. Источники `Я`, `VK`, `YT`, `SC` пока не подключены; без настоящих результатов их бейджи не появляются. |

## Что запрашивать у владельцев интеграций

- **VK:** [черновик запроса в поддержку](vk-access-request.md). Нужны разрешённый сценарий «QR-вход → сессия Luma», публичный ID именно приложения Luma, перечень прав и документация для чтения фонотеки/плейлистов, поиска, воспроизведения и загрузок. Нужна проверка на разрешённом тестовом аккаунте, с подпиской/без и с проверкой геоограничений. Сессия сайта или токен другого клиента не подходят.
- **Яндекс, YouTube, SoundCloud:** разрешённые каталоги, права приложения, публичные параметры и правила воспроизведения, хранения и атрибуции. Документированный API метаданных не даёт права извлекать аудио из YouTube. Лайки — отдельная подтверждаемая операция с записью только после нажатия.
- **Unison:** [публичное описание самостоятельного сервера](https://github.com/Vexorter42/Unison/blob/eaf123555e6d9fdf93b5e97e72f74c36fb23500d/server/README.md) найдено. Владелец выдаёт и отзывает аккаунты; `PUT /v1/sync` заменяет полную копию с проверкой ETag. Нужен согласованный тестовый экземпляр и тест совместимости без изменения настроек и истории Unison, правил конфликтов и удаления данных. Секреты не помещать в чат или репозиторий; доступ тестовым аккаунтам выдаёт владелец сервера.

## OTA: подготовка подписанной сборки

Приложение использует REST GitHub только для релизов этого репозитория. Для обновления проверяются версия, точное имя `Setup` для x64, размер, SHA-256 файла из GitHub и действительная подпись Authenticode с закреплённым SHA-256 сертификата. Подпись и статус отзыва проверяет Windows (`WinVerifyTrust`), без PowerShell. При отсутствии проверки код не запускается. Случайный прикреплённый `.exe`, файл portable и предварительные версии не устанавливаются. Файлы с неудачной проверкой удаляются; запущенный установщик остаётся во временной папке Windows.

В защищённом окружении сборки настройте [подпись electron-builder](https://www.electron.build/code-signing-win.html). Параметр `lumaWindowsSignerSha256` — публичный SHA-256 от DER подписывающего сертификата, не SHA-1 Thumbprint и не секрет. Сборка для ручного теста двух подписанных версий:

```powershell
npm.cmd run build
npm.cmd run package:win -- -c.forceCodeSigning=true -c.extraMetadata.lumaWindowsSignerSha256=<64-hex>
npm.cmd run test:package
```

В данном CI секрета и публичного закрепления сертификата нет. Сборки для тестирования Windows не подставляют значения и не обещают установку из приложения. Релиз 1.0.0 требует Windows-проверки полного списка, в том числе обновления без перезаписи профиля, проверок отказа и сценариев с реальными провайдерами.

## Ручная проверка на Windows 10/11 x64

Проверяйте на тестовом профиле или в виртуальной машине. `test:desktop` подставляет ответы каталогов и выбор пути в нативном диалоге; на одноразовом Windows runner проверяет системный буфер при его доступности. Если в сессии нет рабочего буфера, проверяется IPC с подменой, а нативный сценарий остаётся ручным. `test:package` проверяет файлы пакета. `test:installed` отдельно устанавливает настоящие Setup и Portable на чистом Windows runner: системный запуск ссылки при закрытой и открытой Luma, переустановка того же билда, сохранение профиля, снятие только собственной регистрации. Эти сценарии прошли на [Windows CI](https://github.com/JohnBirlich/VKX-Modded/actions/runs/44960933149). Буфер на runner нечитаем, поэтому прошла только проверка IPC с подменой. Это не проверка UI установленного плеера на Windows 10/11 и не тест двух подписанных версий.

1. **Setup, ссылка и удаление.** Установите Setup в папку с пробелами. Сначала закройте Luma, затем выполните в PowerShell команду ниже. Должна открыться карточка ссылки VK без входа в аккаунт, браузера и автозапуска. Повторите в запущенной Luma с другим ID — карточка должна смениться без второго окна и остановки трека. Удалите Setup: его обработчик не должен оставаться. В чистом профиле запуск Portable не должен регистрировать обработчик.

   ```powershell
   $target = 'https://vk.ru/audio123_456' # Синтетический адрес: карточка не загружает его.
   Start-Process ('luma-player://open?url=' + [Uri]::EscapeDataString($target))
   ```

2. **Сохранение и буфер обмена.** Экспортируйте список через «Поделиться» в новую папку с кириллицей. Проверьте, что отмена ничего не записывает, повторное сохранение спрашивает о замене именно выбранного файла, а импорт `.luma.json` позволяет выбрать/пропустить строки. В тексте нет аудио, путей и адресов. Скопированная ссылка Openverse открывает карточку в Luma; воспроизведение начинается только по нажатию.
3. **Управление звуком.** Проверьте паузу, продолжение, следующий/предыдущий трек физическими клавишами и с экрана блокировки. Для таймера установите 5 минут, отправьте компьютер в сон дольше этого времени: после пробуждения трек на паузе, таймер сброшен. В файл плейлиста таймер не записывается.
4. **Discord Desktop.** Введите публичный Application ID (не токен). После включения при воспроизведении видны название и исполнитель. При паузе, выключении интеграции или выходе статус исчезает. Отдельно проверьте запуск Discord после Luma.
5. **Подписанное обновление.** Используйте две подписанные тестовые версии с одинаковым закреплением сертификата. Сохраните плейлист, очередь и настройки в старой версии; после установки новой проверьте, что профиль сохранился. Отдельно проверьте отмену, другую подпись и несовпадение контрольной суммы на тестовой сборке обновления — ни один установщик не должен запуститься. У публичного неподписанного Setup и у Portable должен остаться только переход к ручному скачиванию.
